- 재검토에서 높음·중간 항목이 남아 있지 않으면 통과. 같은 단계에서 3번 돌려도 해결이 안 되면 멈추고 나에게 상황을 보고한다.

# 1. 환경 준비
- 확인할 것: node(LTS), rustc/cargo, Visual Studio Build Tools(C++ 데스크톱 워크로드), WebView2, codex.
- 없으면 winget으로 설치. Build Tools는 Microsoft.VisualStudio.2022.BuildTools에 --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended".
- 프로젝트 위치는 지금 폴더 D:\dev\lmux다. 이미 lmux-mockups가 들어 있어서 비어 있지 않으니, 스캐폴드 도구가 빈 폴더를 요구하면 임시 폴더에 만든 뒤 옮긴다. Tauri 2 + React + TypeScript + Vite로 구성한다. 스캐폴드 도구가 git 저장소를 자동으로 만들려고 하면 끄고, 생겼으면 .git 폴더를 지운다.

# 2. 제품
- Windows용 가벼운 AI 코딩 에이전트 멀티플렉서. 여러 Claude Code 세션을 한 창에서 분할해 보고, 상태·컨텍스트·사용량을 한눈에 본다. 깃허브에 MIT로 공개 예정.
- 참고 대상은 Orca지만 훨씬 가볍게: 에디터·내장 브라우저·자동화 대시보드는 넣지 않는다.
- 작업 단위는 "프로젝트 폴더 안의 세션". 내 작업의 80%는 SVN 또는 버전 관리 없는 폴더라서 git 워크트리는 Git 프로젝트에서만 쓰는 선택 옵션이다. (이건 Lmux가 사용자 프로젝트에 제공하는 기능이고, Lmux 자체 개발의 git 금지 규칙과는 별개다. 기능 테스트는 임시로 만든 테스트용 저장소에서만 한다.)

# 3. 기술 구조
- 백엔드(Rust): portable-pty(ConPTY)로 세션마다 셸 실행, 출력은 Tauri 채널로 스트리밍, 입력 전달, 리사이즈.
- 프론트(React/TS): xterm.js + WebGL·fit 애드온. 패널 안은 진짜 터미널이다(셸 출력 그대로, 직접 타이핑 가능).
- 화면에 안 보이는 세션은 렌더링하지 않고 Rust 쪽 링버퍼(기본 10,000줄)에만 쌓았다가 보일 때 다시 그린다.
- 셸 프로필: PowerShell 7(없으면 powershell.exe), WSL(wsl.exe -l -q로 배포판 감지, wsl.exe -d <배포판> --cd <경로>), Git Bash, cmd. PowerShell은 UTF-8로 시작해서 한글이 안 깨지게 한다.
- 저장: 앱 데이터 폴더에 JSON(프로젝트, 세션, 화면 배치, 설정).
- 프로젝트 종류 자동 감지: .svn → SVN, .git → Git, 둘 다 없으면 폴더.
- 상태·컨텍스트: Claude Code 훅 사용. 사용자의 프로젝트 파일(SVN 저장소)은 절대 수정하지 않는다. claude --help로 추가 설정 파일을 넘기는 옵션이 있는지 확인해 그 방식으로 훅을 주입하고, 안 되면 사용자 설정에 "LMUX_SESSION_ID 환경변수가 있을 때만 동작하는" 훅을 등록한다(등록 전에 기존 설정을 백업하고 나에게 알린다). 훅은 127.0.0.1 전용 포트로 이벤트를 보낸다. 프롬프트 제출/도구 사용 = 작업 중, 권한·입력 요청 알림 = 입력 대기, Stop = 완료.
- 컨텍스트 = 세션 기록(transcript JSONL)의 마지막 응답 usage(input + cache_creation + cache_read 토큰) ÷ 모델 컨텍스트 크기(기본 200K, 설정 가능). "168K / 200K · 84%"로 표시. 70% 넘으면 주황, 90% 넘으면 빨강. 훅이 없는 에이전트는 "정보 없음".
- 계정 사용량: 계정 = Claude 설정 폴더 단위(Windows %USERPROFILE%\.claude, WSL \\wsl$\<배포판>\home\<사용자>\.claude, 추가 폴더 등록 가능). 30초마다 로컬 로그를 집계해 오늘 토큰과 5시간/주간 사용률을 보여준다. 공식 한도 수치를 확인할 수 없으면 "추정"이라고 표시하고 기준값을 설정에서 바꿀 수 있게 한다. 추측한 숫자를 확정값처럼 보여주지 않는다.
- 같은 파일 충돌 경고: 훅으로 세션별 수정 파일을 기록하고, 같은 프로젝트의 두 세션이 같은 파일을 고치면 배너로 경고한다.
- 변경 사항: SVN은 svn status/diff/update/commit/revert 호출(svn CLI가 없으면 설치 안내), 세션별로 고친 파일 표시, 커밋 메시지 작성 도움. Git은 status/diff/commit과 워크트리 생성·합치기·삭제. 커밋·되돌리기·삭제는 항상 사용자 확인 후 실행.
- 알림: Windows 토스트.

# 5. 화면
- 메인: 상단(로고, Ctrl+K 검색, 계정별 사용량 막대, 폰 연결 표시, 알림, 설정) / 왼쪽 사이드바(프로젝트별로 묶은 세션, 각 세션에 상태 점·컨텍스트 %·미니 막대, 새 세션 버튼) / 오른쪽 패널 영역.
- 패널 헤더: 상태, 세션 이름, 프로젝트·경로·셸·에이전트, 컨텍스트 링 + 토큰 숫자. 입력 대기 패널은 주황 테두리, 아래에 승인 버튼 줄(누르면 터미널에 1/2/3 + Enter 입력).
- 분할: 레이아웃 버튼(1개/2개/1+2/2×2), 사이드바 세션이나 패널 헤더를 끌어 위·아래·좌·우·가운데에 놓기(놓을 영역 미리 표시), 경계선 끌어 크기 조절(더블클릭하면 반반), 단축키(Ctrl+\ 오른쪽 분할, Ctrl+Shift+\ 아래 분할, Ctrl+1~4 패널 이동, Ctrl+Shift+Enter 최대화), 화면 배치 저장·불러오기.
- 프로젝트 추가(폴더 선택, 종류 자동 감지, 기본 셸·에이전트), 새 세션(프로젝트, 이름·첫 지시, 프로젝트 폴더에서 바로 / Git 워크트리, 셸, 에이전트, 계정, 같은 폴더 세션 경고), 변경 사항·커밋, 계정·사용량, 모바일 연동, 설정 6개(셸 프로필, 알림, 화면, 성능, 단축키, 정보·업데이트).

# 6. 단계 (각 단계는 0-1 순서를 따른다)
1. 창 + PowerShell 패널 1개가 진짜 터미널로 동작
2. 셸 프로필(WSL/PowerShell/Git Bash/cmd), 프로젝트 등록과 종류 감지, 사이드바, 세션 여러 개
3. 화면 분할 전체(버튼·드래그·경계선·단축키·배치 저장)
4. 훅으로 상태·컨텍스트 표시, 승인 버튼 줄, Windows 알림
5. 계정 사용량 30초 갱신
6. 변경 사항: SVN/Git, 같은 파일 충돌 경고, Git 워크트리
7. 설정 6개 화면, 트레이, 절전 막기, 세션 복원
8. (확인받고 시작) 모바일: Tailscale IP(100.x)에만 바인딩(0.0.0.0 금지), tailscale cert로 HTTPS, QR 1회용 + 6자리 확인 후 PC 승인, 기기별 토큰(해시 저장)·권한(보기/입력)·해제, PWA로 세션 목록·원격 터미널·파일 보기(등록 폴더 안 읽기 전용, 경로 탈출 차단, .env·키 파일 숨김), 새 셸 열기 금지, 접속 기록, Web Push 알림(기본은 내용 없이)
9. README(한국어/영어), MIT LICENSE, GitHub Actions 워크플로 파일(Windows 설치 파일 빌드) 작성. 파일만 만들고 git 작업은 하지 않는다.
