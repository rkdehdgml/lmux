## 0·1단계

| # | 결정 | 이유 |

| D1 | 패키지 매니저는 npm | 추가 설치 없이 GitHub Actions에서도 그대로 동작 |
| D2 | 앱 식별자 `io.github.lmux.app`, 설치 파일은 NSIS만 | MIT 깃허브 공개 전제. NSIS는 관리자 권한 없이 설치 가능. 식별자는 저장소 주소가 정해지면 바꿀 수 있음(바꾸면 앱 데이터 폴더가 달라짐) |

| D6 | 다시 붙을 때: 먼저 리사이즈 → 링버퍼 재생 → 실시간 출력. 재생 중 xterm의 자동 응답은 셸로 보내지 않음 | 재생에 섞인 터미널 질의에 응답하면 셸에 쓰레기 입력이 들어감 |

| D9 | Ctrl+C는 선택이 있으면 복사·없으면 인터럽트, Ctrl+V는 붙여넣기 | Windows Terminal 관례 |

| D12 | Rust 툴체인 재설치 | 기존 설치에 `rustc.exe`가 없어 덮어쓰기도 실패. 사용자 영역이라 관리자 권한 불필요(rustc 1.100.0) |

## 2단계

| # | 결정 | 이유 |
|---|---|---|
| D20 | 에이전트는 셸 안에서 명령 한 줄로 실행. PowerShell은 `-Command`, Git Bash·WSL은 로그인 셸의 `-c` 뒤 대화형 셸로 넘어감(명령은 환경 변수 `LMUX_CMD`로 전달하고 에이전트 실행 전에 지움). cmd만 셸이 뜬 뒤 입력하며 이때는 AutoRun을 건너뜀(`/D`) | 셸 시작 파일이 입력을 읽어도 명령을 빼앗기지 않고, 에이전트가 끝나도 셸이 남음. 한계: 에이전트가 끝난 뒤 남는 셸은 비로그인 셸이며 `.bashrc`를 다시 읽음. WSL은 bash(없으면 sh)의 시작 파일로 에이전트를 찾으므로 다른 셸 설정에만 둔 `PATH`는 보지 못함. cmd 에이전트 세션에는 AutoRun으로 넣는 도구(clink 등)가 없음 |
| D21 | 첫 지시는 인수 하나로 넘김. 줄바꿈·제어 문자는 공백, PowerShell·cmd는 `"`→`'`, `%`→`％`, 4000자 제한 | 입력한 글이 셸 명령으로 실행되지 않게 함(`.cmd` 셔임 포함, 실제 셸 테스트). 저장하지 않고 첫 시작에만 사용 |
| D22 | 종류 감지는 상위 폴더까지 보고 가까운 쪽 우선, 같은 위치면 SVN | SVN 작업 사본의 하위 폴더를 프로젝트로 쓰는 경우 |
| D23 | WSL 목록에서 `docker-desktop*` 제외, `wsl.exe -l -q`는 5초 제한 | 작업용 셸이 아님. WSL이 멈춰도 앱은 동작 |
| D24 | 새 의존성 `tauri-plugin-dialog`(폴더 선택), 권한은 `dialog:allow-open`만 | 시안의 "찾아보기". 공식 플러그인 |
| D25 | 앱을 켜면 세션을 자동으로 시작하지 않고 고를 때 시작 | 에이전트가 모르게 실행되지 않게 함. 세션 복원은 7단계 |
| D26 | 아직 동작하지 않는 것은 화면에 두지 않음(분할 버튼, 컨텍스트, 계정, 워크트리, 검색, 설정). "같은 파일을 고치면 알려드려요" 문구는 6단계까지 바꿔 씀 | 동작하지 않는 기능을 약속하지 않음. Ctrl+K 검색은 7단계에서 |
| D27 | 자식 셸의 환경 변수는 `portable-pty` 동작대로 레지스트리 값이 우선 | Windows Terminal처럼 새로 설치한 도구가 바로 잡힘. 터미널에서 임시로 바꾼 `PATH`는 전달되지 않음 |
| D28 | `LMUX_DATA_DIR` 환경변수가 있으면 저장 폴더로 사용 | 확인 스크립트가 실제 데이터를 건드리지 않게 함 |
| D29 | cmd에서 Claude·Codex를 부를 때 `NoDefaultCurrentDirectoryInExePath`를 설정 | cmd는 현재 폴더를 먼저 찾아 프로젝트에 심은 프로그램이 실행될 수 있음. 그 세션에서는 이후에도 현재 폴더의 프로그램은 `.\이름`으로 불러야 함. 직접 입력 명령은 바꾸지 않음 |
| D30 | 데이터 폴더의 `state.lock`을 앱이 켜진 동안 독점 | 두 창이 목록을 서로 덮어쓰지 않게 함. 추가 의존성 없음 |
| D31 | 첫 지시는 첫 시작에 한 번만 사용 | 셸이 시작 직후 죽어 실행되지 못해도 자동으로 다시 보내지 않음. 에이전트가 받았는지 알 수 없어 자동 재전송은 중복 실행이 됨 |
| D32 | 다른 창이 데이터를 쓰는 중이면 두 번째 창에서는 세션을 시작하지 않음 | 같은 폴더에 에이전트가 겹쳐 뜨고 경고가 빠지는 것을 막음 |
| D33 | 화면 배치는 패널 최대 4개의 이진 분할 트리. 분할 단축키도 4개에서 멈춤 | 단축키가 `Ctrl+1~4`이고 시안의 가장 큰 배치가 2×2 |
