# 4단계 훅 상태·컨텍스트·승인·알림 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans(직접 구현) 또는 superpowers:subagent-driven-development. 작업마다 superpowers:test-driven-development. 단계 규칙은 `CLAUDE.md`(구현 → 빌드 → 테스트 → 직접 실행 → Codex·Claude 검토, 높음·중간 0까지 반복 → `backups/stage-4.zip`). git 명령은 사용자가 지시할 때만.

**Goal:** Claude Code 세션의 상태·컨텍스트를 훅으로 받아 화면에 보이고, 승인 단추와 Windows 알림을 제공한다.

**Architecture:** `--settings <세션별 파일>`로 훅·statusLine을 주입하고, `127.0.0.1` 서버가 받은 이벤트를 순수 함수로 상태에 반영해 Tauri 이벤트로 화면에 보낸다.

**Tech Stack:** Rust(`tiny_http`, `tauri-plugin-notification`, 기존 `serde_json`), React/TS.

**Spec:** `docs/superpowers/specs/2026-11-27-stage-4-design.md`(결정 11개, 가정 A1~A6), `docs/spec.md` 3·4·5절. 시안 `docs/mockups/Main.dc.html`, `Layout3.dc.html`.

## Global Constraints
- 사용자 프로젝트·`~/.claude`는 수정하지 않는다. 서버는 `127.0.0.1`만.
- 컨텍스트 색: 50% 이상 주황, 90% 이상 빨강. 훅이 없는 에이전트는 상태·컨텍스트 없음.
- 새 명령은 `lib.rs` 핸들러, `build.rs` COMMANDS, `capabilities/default.json` 세 곳에 추가한다. 알림은 `notification` 권한 추가.
- 실제 Claude·Codex는 Task 0 외에는 띄우지 않는다. 확인 스크립트는 가짜 `claude`를 쓰고 먼저 잡히는지 확인한다(`scripts/e2e/stage-2.sh` 방식, D27).
- 기존 테스트(프론트 35, Rust 65)와 `stage-2.sh`·`stage-3.sh`가 계속 통과해야 한다.

## Review Focus
1. 다른 프로그램이 가짜 이벤트(틀린 토큰, 다른 세션 id, 1MB 초과)를 보내도 상태가 바뀌지 않는다.
2. Lmux가 꺼져 있거나 서버가 응답하지 않아도 Claude가 멈추지 않는다(훅이 항상 정상 종료).
3. 오래된 승인 단추 클릭(이미 답했거나 다른 요청으로 바뀜)은 터미널에 아무것도 입력하지 않는다.
4. 세션을 다시 시작하거나 지운 뒤 늦게 도착한 이벤트가 새 실행의 상태를 바꾸지 않고, 설정 파일이 남지 않는다.
5. WSL 세션의 설정 파일 경로·transcript 경로 변환이 맞고, 안 닿으면 그 세션만 "정보 없음"이다.
6. 큰 transcript(수백 MB)를 읽어도 UI가 멈추지 않고, 서브에이전트 항목은 컨텍스트에 섞이지 않는다.

### Task 0: 가정 확인 (실제 Claude 1회)
**Files:** Create `docs/superpowers/notes/stage-4-probe.md`
- [ ] 사용자에게 알린 뒤 승인받는다(폴더 신뢰 화면을 사용자가 눌러야 할 수 있음). 임시 폴더에서 `claude --settings <덤프용 파일>`로 한 번만 실행하고 짧은 요청과 승인 요청이 한 번씩 나오게 한다.
- [ ] 덤프용 설정: 모든 이벤트(`UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `Stop`, `SessionEnd`)와 `statusLine`이 stdin JSON을 파일에 쓰게 한다. 사용자 훅이 있으면 함께 실행되는지(A1)도 본다.
- [ ] 기록: 각 이벤트의 필드 이름(`session_id`, `transcript_path`, 요청 구분 값), statusLine의 `context_window_size`·`used_percentage`(A2·A3), 승인 화면에서 `1\r`이 동작하는지(A5). 가정이 틀리면 설계서 3절의 대체안을 적고 이후 작업을 바꾼다.
- [ ] 사용자 데이터(대화 내용)가 노트에 남지 않게 필드 이름과 숫자만 적는다.

### Task 1: 훅 이벤트 해석과 상태 계산 — `src-tauri/src/events.rs`
**Interfaces — Produces:**
- `enum Hook { Prompt, ToolUse, Permission { request: String }, Stop, End }`
- `struct Context { used: u64, size: u64, estimated: bool }`
- `enum Live { Working, Waiting { request: String }, Done }`
- `fn parse(event: &str, body: &[u8]) -> Result<Hook, String>`(Task 0 결과의 필드 이름에 맞춘다)
- `fn parse_status(body: &[u8]) -> Option<Context>`
- `fn next(now: Option<Live>, hook: Hook) -> Option<Live>`(`End`는 `None`)
- [ ] 테스트: 각 이벤트의 성공, 알 수 없는 이벤트·깨진 JSON 거절, 상태 전이(작업 중 → 승인 대기 → 작업 중 → 완료), `Stop` 뒤 `PreToolUse`가 와도 작업 중으로 돌아감.
- [ ] 실패 확인 → 구현 → `cargo test events` 통과.

### Task 2: 컨텍스트 계산 — `src-tauri/src/context.rs`
**Interfaces — Produces:** `fn from_transcript(path: &Path) -> Option<Context>`(끝에서 최대 2MB만 읽는다, `isSidechain`·usage 없는 줄 제외, `estimated: true`, 크기 200_000), `fn windows_path(distro: Option<&str>, path: &str) -> PathBuf`(WSL 리눅스 경로 → `\\wsl$\<배포판>\…`)
- [ ] 테스트: 마지막 assistant usage 합산, sidechain 무시, 빈 파일·잘린 마지막 줄, 큰 파일에서도 끝부분만 읽음(파일 크기 대비 읽은 바이트), WSL 경로 변환.
- [ ] 실패 확인 → 구현 → 통과.

### Task 3: 설정 파일 생성과 훅 명령 — `src-tauri/src/hooks.rs`
**Interfaces — Consumes:** Task 1 이벤트 이름. **Produces:** `fn settings_json(port: u16, session: &str, token: &str, wsl: bool) -> String`(훅 5종 + statusLine, 모두 `curl.exe ... || true`와 같은 정상 종료, `timeout: 5`), `fn write(dir, session, ...) -> io::Result<PathBuf>`, `fn remove(dir, session)`, `fn remove_all(dir)`
- [ ] 테스트: 생성된 JSON이 유효하고 URL에 세션·토큰만 들어가며 외부 입력(경로·프롬프트)이 없음, 훅 명령이 실패 시에도 종료 코드 0, 삭제·전체 삭제, 앱 시작 때 남은 파일 청소.
- [ ] 실패 확인 → 구현 → 통과.

### Task 4: 수신 서버 — `src-tauri/src/hook_server.rs`
**Interfaces — Consumes:** Task 1·2. **Produces:** `struct HookServer`, `fn start(on_event: impl Fn(SessionEvent) + Send + 'static) -> io::Result<HookServer>`, `fn port()`, `fn register(session, token) -> ()`, `fn unregister(session)`
- [ ] 테스트(로컬 소켓으로 실제 요청): 올바른 토큰은 200과 이벤트 전달, 틀린 토큰·모르는 세션 404, 1MB 초과 413, 느리게 보내는 연결이 서버 전체를 막지 않음(스레드 또는 타임아웃), `127.0.0.1`에만 바인드.
- [ ] 실패 확인 → 구현(`tiny_http`) → 통과.

### Task 5: 세션 시작에 연결 — `agent.rs`, `workspace.rs`, `session.rs`, `lib.rs`, `build.rs`, `capabilities/default.json`
**Interfaces — Consumes:** Task 3·4. **Produces:** `command_line`에 Claude일 때만 `--settings <경로>`(경로는 기존 인수 규칙으로 감싼다, WSL은 `wslpath` 결과), 명령 `session_approve(id: String, run: u64, request: String, choice: u8) -> Result<(), String>`, Tauri 이벤트 `session-state { id, run, live, context }`
- [ ] 테스트: Claude가 아닐 때 `--settings`가 없다, 셸 4종 인수 형태, 세션 삭제·프로젝트 해제·앱 종료 때 파일 삭제, 실행 번호가 바뀌면 상태 초기화·이전 이벤트 무시, `session_approve`는 요청 번호와 상태가 맞을 때만 `"{choice}\r"`를 쓰고 아니면 오류(Review Focus 3·4).
- [ ] 실패 확인 → 구현 → `cargo test`, `cargo clippy -- -D warnings` 통과.

### Task 6: 화면 — `model.ts`, `SessionPanel.tsx`, `Sidebar.tsx`, `App.tsx`, `api.ts`, `styles.css`
**Interfaces — Consumes:** Task 5 이벤트·명령.
- [ ] 테스트(`model.test.ts`): 훅 상태가 있으면 그 상태를 우선, 없으면 기존 상태 글자, 컨텍스트 색 경계(49/50/89/90%), 크기 표기(`168K/200K`), 추정 표시.
- [ ] 구현: 사이드바 점·%·미니 막대, 머리글 링·숫자, 승인 대기 주황 테두리와 단추 줄(`1 · 예`, `2 · 세션 동안 허용`, `3 · 아니요`), 상태가 바뀌면 단추 사라짐, 오류는 배너로.
- [ ] `npm run build`, `npm test` 통과.

### Task 7: 알림 — `tauri-plugin-notification`
- [ ] `Cargo.toml`·`lib.rs`·`capabilities/default.json`에 추가. 승인 대기·완료 이벤트에서 창이 활성이 아닐 때만 `세션 이름 + 상태` 알림(내용 없음). 알림 로직은 "보낼지 말지" 순수 함수로 분리해 테스트(활성 창이면 안 보냄, 같은 상태 반복 안 보냄).
- [ ] 직접 확인: 창을 다른 창 뒤로 두고 가짜 이벤트를 보내 알림이 뜨는지.

### Task 8: 직접 실행 확인 — `scripts/e2e/stage-4.sh`
- [ ] 가짜 `claude`가 설정 파일의 훅 명령을 그대로 실행해 이벤트를 보내게 한다(`UserPromptSubmit` → `PermissionRequest` → `Stop`). 확인: 사이드바·머리글 상태 변화, 컨텍스트 색(49/50/90%), 승인 단추 → 가짜 claude가 `1\r`을 받음, 오래된 클릭 무시, 틀린 토큰의 가짜 이벤트 무시, Lmux 종료 후에도 가짜 훅이 정상 종료(Review Focus 2), 세션 삭제 후 설정 파일 없음, WSL 세션(가짜 claude, 미러 모드), 두 번째 실행 뒤 `stage-2.sh`·`stage-3.sh` 통과.
