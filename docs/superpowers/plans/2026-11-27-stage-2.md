# 2단계 구현 계획: 셸 프로필 · 프로젝트 · 사이드바 · 다중 세션

> 실행 방식: Claude가 직접 구현(superpowers:executing-plans), 단계 끝에 Codex 검토. 체크박스로 진행 표시.

**Goal:** 프로젝트를 등록하고, 셸·에이전트를 골라 세션을 여러 개 만들어 사이드바에서 오가며, 다시 켜도 목록이 남는다.

**Architecture:** 저장 상태(프로젝트·세션 기록)는 Rust가 JSON으로 소유한다. 프론트는 기록 id만 넘기고, 실행 명령·시작 폴더는 Rust가 기록에서 만든다. 에이전트는 셸이 뜬 뒤 명령 한 줄을 입력해 실행한다(셸별 인수 인용 문제를 피하고, 사용자가 무엇이 실행됐는지 본다).

**Spec:** `docs/spec.md` 3·4·5·6절. 시안: `docs/mockups/Main.dc.html`, `NewProject.dc.html`, `NewSession.dc.html`.

> 구현 중 바뀐 점: 검토 결과에 따라 에이전트 실행 방식이 아래 설계(셸에 입력)에서 `decisions.md` D20(시작 인수, cmd만 입력)으로 바뀌었다.

## 제약
- 셸: PowerShell 7(없으면 powershell.exe), WSL(`wsl.exe -l -q`, `wsl.exe -d <배포판> --cd <경로>`), Git Bash, cmd. PATH 탐색 없이 정해진 설치 위치만(D14).
- 종류: `.svn`→SVN, `.git`→Git, 없으면 폴더. 배지 색 SVN `#C3A8FF`, Git `#7FD8AE`.
- 저장: 앱 데이터 폴더의 JSON. 사용자의 프로젝트 폴더에는 아무것도 쓰지 않는다. 프로젝트·세션 삭제는 확인 후, 등록만 지운다.
- 안 보이는 세션은 렌더링하지 않는다.
- 이 단계에 없는 것(동작하지 않는 버튼은 만들지 않음): 분할(3), 컨텍스트·상태 훅·알림(4), 계정(5), 워크트리·변경 사항(6), 셸 프로필 편집·검색·설정·세션 복원(7).
- 새 명령은 `lib.rs`·`build.rs`·`capabilities/default.json` 세 곳에 추가.

## Review Focus
1. 첫 지시에 따옴표·`&`·`%`·`$()`·줄바꿈이 있어도 셸이 그것을 명령으로 실행하지 않는다.
2. 저장 파일이 깨졌거나 더 새 버전이면 조용히 덮어쓰지 않는다.
3. 등록한 폴더가 지워졌으면 다른 폴더에서 셸을 띄우지 않고 오류를 보여 준다.
4. WSL이 없거나 `wsl.exe`가 멈춰도 앱과 나머지 셸 목록은 동작한다.
5. 세션을 빠르게 오가도 출력·입력이 다른 세션에 섞이지 않는다.

## Task 1: 에이전트 명령 줄 (`agent.rs`)
- Produces: `enum ShellKind { PowerShell, Cmd, Posix }`, `enum Agent { None, Claude, Codex, Custom }`(serde 소문자), `fn command_line(kind, agent, custom: &str, prompt: &str) -> Option<String>`
- [ ] 테스트: 없음→None. `Claude`+빈 지시→`claude`. PowerShell은 작은따옴표로 감싸고 `'`는 두 번. Posix는 `'\''`. cmd는 큰따옴표, `%`→`％`. 모든 셸에서 `"`→`'`, 줄바꿈·탭·제어 문자→공백. 공백 없는 지시는 끝에 공백 추가(.cmd 셔임에서 `&` 분리 방지). 끝의 `\` 제거. `Custom`은 사용자가 쓴 명령 그대로(제어 문자만 공백).
- [ ] 통합 테스트: PowerShell·cmd·Git Bash 실제 실행에서 `a&b "c" %PATH% $(x)` 지시가 한 인수로 전달됨.

## Task 2: 셸 감지와 시작 (`shell.rs`)
- Produces: `struct ShellInfo { id: String, name: String, kind: ShellKind }`(id: `powershell`, `wsl:<배포판>`, `gitbash`, `cmd`), `fn list() -> Vec<ShellInfo>`, `fn command(id: &str, cwd: &str) -> Result<(CommandBuilder, ShellKind), String>`, `fn parse_wsl_list(bytes: &[u8]) -> Vec<String>`, `fn wsl_path(cwd: &str, distro: &str) -> String`
- [ ] 테스트: UTF-16LE 목록 해석(BOM·CR·빈 줄), `docker-desktop*` 제외, `\\wsl$\Ubuntu\home\a`·`\\wsl.localhost\…`→`/home/a`, 다른 배포판의 UNC는 오류, 알 수 없는 id 오류, 없는 폴더 오류, cmd+UNC 오류.
- [ ] `wsl.exe` 호출은 창 없이, 5초 제한.
- [ ] 통합 테스트: 설치된 셸마다 시작 폴더에서 한글 출력.

## Task 3: 저장소 (`store.rs`)
- Produces: `struct Project { id, name, path, kind: Kind, default_shell, default_agent }`, `struct SessionRecord { id, project_id, name, shell, agent, custom_command }`, `struct State { version: u32, next_id: u64, projects, sessions }`, `struct Store { open(dir) -> (Store, Option<String>), state(), add_project, remove_project, add_session, remove_session }`, `fn detect_kind(path) -> Kind`
- [ ] 테스트: 종류 감지(상위 폴더 포함, 가까운 쪽 우선, 같은 위치는 SVN), 저장 후 다시 열기, 임시 파일+이름 바꾸기, 깨진 파일은 `.bak`으로 보존하고 경고, 더 새 버전은 읽기 전용 오류, 같은 폴더 중복 등록 거절, 없는 폴더 거절, 빈 이름 거절, 프로젝트 삭제 시 그 세션 기록 삭제, 프로젝트 폴더 안 파일 불변.
- 첫 지시는 저장하지 않는다(처음 시작할 때만 사용).

## Task 4: 명령과 시작 명령 입력
- Consumes: Task 1~3.
- `Sessions::start(id, cmd, cols, rows, startup: Option<String>, on_exit)`: 시작 커서 질의에 답한 직후(질의가 없으면 시작 범위를 지난 뒤) `startup + "\r"`을 한 번만 입력.
- 명령: `app_state`, `shells_list`, `project_detect`, `project_add`, `project_remove`, `session_create(…, prompt) -> SessionRecord`, `session_delete`, `session_start(id, cols, rows)`. `LMUX_DATA_DIR`이 있으면 저장 폴더로 사용(확인 스크립트용).
- [ ] 테스트: 시작 명령이 질의 응답 뒤에 한 번만 입력됨. 첫 지시는 첫 시작에만 쓰고, 다시 시작하면 에이전트 명령만.
