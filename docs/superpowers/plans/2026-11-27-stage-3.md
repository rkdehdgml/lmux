# 3단계 화면 분할 구현 계획

> 실행: superpowers:executing-plans(직접 구현), 작업마다 TDD. git 명령은 쓰지 않는다. 마지막 독립 검토는 Codex.

**Goal:** 레이아웃 단추, 끌어다 놓기, 경계선 크기 조절, 단축키, 배치 저장·불러오기.

**Architecture:** 배치는 이진 분할 트리(패널 최대 4개). 순수 함수 `src/layout.ts`가 모든 조작을 맡고, 화면은 트리에서 계산한 좌표에 패널을 **절대 위치**로 그린다(세션 id를 키로 써서 배치를 바꿔도 터미널을 다시 만들지 않음). 끌기는 포인터 이벤트. 저장은 Rust `state.json`.

**Spec:** `docs/spec.md` 5절 "분할", 시안 `docs/mockups/Layout1~3.dc.html`.

## Global Constraints
- 레이아웃: 1개 / 2개 / 1+2 / 2×2, "좌우 ↔ 상하", 저장된 화면.
- 단축키: `Ctrl+\` 오른쪽 분할, `Ctrl+Shift+\` 아래 분할, `Ctrl+1~4` 패널 이동, `Ctrl+Shift+Enter` 최대화. 앱이 가져간 키는 셸에 보내지 않는다.
- 놓을 영역 미리 표시, 경계선 끌기(더블클릭 = 반반).
- 사용자 프로젝트 폴더에 쓰지 않는다. 앱을 켜도 세션을 자동 시작하지 않는다.

## Review Focus
1. 빈 패널로 이동한 뒤 친 글자가 이전 터미널로 가지 않아야 한다.
2. 배치를 바꿔도 보이는 터미널의 내용이 다시 그려지거나 사라지지 않아야 한다.
3. 삭제한 세션이 저장된 배치에 남아 있어도 불러오기가 깨지지 않아야 한다.
4. 대화 상자가 열려 있으면 단축키가 동작하지 않아야 한다.
5. 끌기를 Esc·창 전환으로 취소하면 배치가 바뀌지 않고, 끌기 뒤에 클릭이 함께 실행되지 않아야 한다.

## Task 1: 배치 모델 — `src/layout.ts`, `src/layout.test.ts`
**Produces:**
- `type Dir = "row" | "col"`, `type Node = { type: "pane"; session: string | null } | { type: "split"; dir: Dir; ratio: number; first: Node; second: Node }`
- `type Preset = 1 | 2 | 3 | 4`, `type Zone = "center" | "left" | "right" | "top" | "bottom"`, `type View = { tree: Node; focus: number }`
- `leaves(tree)`, `preset(view, n)`, `presetOf(tree)`, `show(view, session)`, `split(view, dir): View | null`, `drop(view, session, target, zone): View | null`, `dropZone(tree, session, target, zone)`, `resize(tree, path, ratio)`(0.15~0.85), `transpose(tree)`, `prune(tree, ids)`(없는 id·중복은 빈 패널), `geometry(tree)`, `zoneAt(x, y)`
- [ ] 테스트 작성 → 실패 확인 → 구현 → `npm test` 통과
